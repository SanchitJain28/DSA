# DSA Revision Strategy

## Core Principle
Spaced repetition + interleaving. Never let old topics go untouched for weeks.

## Daily Time Split (4 hrs total)
- **New topic:** 2.5–3 hrs
- **Revision :** 45 min – 1 hr
- **Weekly mixed set:** once a week, replaces new-topic time for that session

## Spaced Review Intervals
Review each solved problem at:
- Day 1
- Day 3
- Day 7
- Day 15
- Day 30

**Rule:** Confident recall → push interval further out. Struggled → reset to Day 1.

## How to Revise (per problem)
1. **Recall first** — mentally reconstruct the approach before looking at old code (2–3 min).
2. **Got it right** → skim old code, move on. Don't re-type.
3. **Got it wrong** → re-solve fully, reset interval to Day 1.
4. After Day 3, most revisions should be mental recall only — not full re-solving.

## Weekly Mixed-Topic Set
Pick 4–5 random problems across ALL topics solved so far. Solve without knowing the topic in advance. Tests real pattern recognition, not memorized context.

## Tracking
Log every problem in a sheet with:
`Topic | Problem | Pattern | Core Idea | Date Solved | Confidence (1-5) | Last Reviewed | Next Review | Review Count | Notes | Link`

Sort by `Next Review` daily to know what's due.

## Pattern Sheets
One page per pattern (Monotonic Stack, Two Pointer, Sliding Window, etc.) containing:
- Core template/trick
- 2–3 problems where it applies
- Common bug/edge case

Re-reading this refreshes a whole topic in ~5 min.

## Red Flags
- Revision consistently >1.5 hrs/day → too many resets; intervals or confidence ratings need recalibration.
- High review count + still low confidence on a pattern → needs a dedicated re-study day, not just daily revision.
